# Задачи для Cursor — внедрение курса

Каждая задача — отдельный агент, отдельная ветка от свежего `main`, PR и `ship`. Порядок важен: C1 → C2 → C3; C4–C6 и C8 можно параллельно после C2. Перед каждой: `git checkout main && git pull`.

---

## C1 · Схема курса (`feat/course-schema`)

```
Прочитай docs/COURSE.md, docs/COURSE-A1.md и content/course-plan.json.

Задача: добавить в контент-модель уровень «модуль» и сущности «Основи», «Звуки», «Чекпоинт», не ломая существующие темы и уроки.

1. Типы (src/content/types.ts или где лежат текущие типы контента):
   - CourseUnit { id, level, title, topicIds[], grammarIds[], soundIds[], checkpointId? }
   - GrammarCard { id, level, title, focus, examples[] (es), exercises? }
   - SoundLesson { id, title, focus, items[] }
   - Checkpoint { id, level, title, format }
   - Topic: добавить необязательные поля unitId, canDo (локализованный {ru,uk,en}), starterDay.
   Все пользовательские тексты — локализованные объекты {ru,uk,en}, как у существующего контента.
2. Zod-схема для content/course-plan.json (version 1) + тест, что текущий файл валиден.
3. scripts/content/check.ts: проверки — все topicIds из плана существуют либо помечены planned; grammar/sound/checkpoint ids ссылаются на существующие; уникальность id.
4. Никаких изменений UI. npm run check зелёный, тесты на новую валидацию.
```

## C2 · Импорт плана A1 (`feat/course-import-a1`)

```
Прочитай docs/COURSE-A1.md и content/course-plan.json (уровень A1).

Задача: привести существующие темы A1 к плану, СОХРАНИВ существующие id тем и items (на них ссылаются FSRS-карточки и папки пользователей).

1. Напиши скрипт scripts/content/import-plan.ts:
   - читает course-plan.json;
   - для каждой темы A1, у которой есть content/items/a1/<topic>.json и уроки: сопоставляет items по нормализованному es-тексту (без регистра, знаков ¿?¡!.,… и лишних пробелов). Совпавшие — оставляет id и аудио; новые — добавляет с новыми id и draft: true; отсутствующие в плане — НЕ удаляет, а печатает отчёт;
   - выставляет unitId, порядок уроков, title/goal (ru из плана; uk/en — пометить TODO для пайплайна переводов);
   - создаёт content/units/a1.json по плану.
   - режим --dry-run печатает diff-отчёт, без него — пишет файлы.
2. Запусти с --dry-run, вставь отчёт в описание PR, затем без него.
3. Новые темы (hora, estados, familia, casa, farmacia, gimnasio, hotel, aeropuerto, planes) пока создай как планы без items — их генерирует C3.
4. Существующие id items не меняются ни при каких условиях — добавь тест, который сравнивает список id до/после.
5. npm run content:check и npm run check зелёные.
```

## C3 · Генерация недостающих тем A1 (`content/a1-new-topics`)

```
Для тем A1 из content/course-plan.json, у которых нет items (hora, estados, familia, casa, farmacia, gimnasio, hotel, aeropuerto, planes), а также для новых items в существующих темах:

1. Сгенерируй items по формату content/items v2: es, tr {ru,uk,en}, say (транскрипция кириллицей и латиницей по нашему формату), parts с буквальным переводом, note/why где это полезно (в плане — note_ru; пометку 🌎 сохраняй как отдельное поле variant: "es-419"), draft: true.
2. ru бери из плана как есть; uk и en переведи сам, естественно, не дословно.
3. Уроки собери строго по плану (порядок и состав items). Сценку темы (dialog) напиши из 6–8 реплик, используя только фразы этой и предыдущих тем.
4. Ничего не озвучивай — озвучка отдельным шагом (npm run content:tts) после ревью.
5. npm run content:check зелёный. В PR — таблица: тема, уроков, items, сколько draft.
```

## C4 · «Основи» в приложении (`feat/osnovy`)

```
Прочитай docs/COURSE.md, раздел «Структура» и «Шаблон темы».

1. Сгенерируй content/grammar/a1/*.json для g.a1.01–g.a1.21 по плану: заголовок, правило в 2–3 коротких предложениях {ru,uk,en}, 3 примера — ТОЛЬКО фразы из уже пройденных уроков (бери из content/items), 5 упражнений (выбор формы, собрать фразу, вставить пропуск). draft: true.
2. Экран карточки «Основи» в стиле нашего урока: правило → примеры с аудио → упражнения → итог. 3–5 минут.
3. После завершения первого урока темы, где модуль содержит grammarIds, на экране итога предлагать «Коротко о правиле» (не блокирует путь).
4. Список всех «Основ» — в Профиле (пройденные / доступные / закрытые).
5. Прогресс — локально + Supabase (новая таблица grammar_progress с RLS и pgTAP, миграция только локально).
6. Все строки UI — через i18n (ru, uk, en). Тесты на навигацию и сохранение прогресса.
```

## C5 · «Звуки» (`feat/sound-lab`)

```
1. content/sounds/*.json для s.01–s.08 по плану: объяснение 2 предложениями, 6–8 слов/фраз (из уже пройденных, где возможно), минимальные пары (pero/perro, papa/papá, casa/caza для Испании).
2. Экран мини-урока: послушай → повтори (используем существующую проверку произношения и правила silent h, j/x, rr, ударение).
3. Если в шаге speak сработало правило (например, произнесена h), на итоге урока показывать «Потренировать звук: Немая H».
4. Карточка «Звук дня» в «Сегодня», если есть непройденные звуки и пользователь прошёл ≥3 урока.
5. i18n, тесты.
```

## C6 · Чекпоинты (`feat/checkpoints`)

```
1. cp.a1.week1: сценка «Первый разговор» на день 7 стартовой недели (диалог из тем hola, cafe, numbers, tienda, camino, restaurante). Без оценки — в конце «Что получилось» и «Что повторить».
2. cp.a1.final: тест из 4 частей (аудирование, чтение, письмо — собрать сообщение из блоков, говорение — 3 вопроса с проверкой произношения). 20 заданий, порог 60%. Задания генерируются из items A1 (без draft).
3. Результаты: таблица checkpoint_results (RLS + pgTAP), экран результата, слабые темы → в «Повторить».
4. Чекпоинт не блокирует следующие темы.
5. i18n, тесты.
```

## C7 · Пакетная генерация A2–B2 (`content/a2-u01-u02` и т. д.)

```
Возьми из content/course-plan.json модули <A2-U01, A2-U02> (не больше двух модулей за PR).

Для каждой темы:
1. Разбей на planned_lessons уроков по 6–7 items. Ключевые фразы из плана обязательны; остальное добери естественными фразами той же ситуации. ≥ 70% — фразы.
2. Используй грамматику модуля (grammar_ids) и не используй грамматику следующих модулей. Лексика — повторно используй слова из прошлых уровней, где возможно.
3. Формат items v2, draft: true, сценка 8–10 реплик.
4. Карточки «Основи» для grammar_ids модуля — как в C4.
5. npm run content:check зелёный; в PR таблица тема/уроки/items и список новых грамматических конструкций.
```

## C8 · Новые типы упражнений из практики с репетитором (`feat/exercise-types`)

```
Прочитай docs/TUTOR-MAP.md, раздел 6. Добавь в генератор уроков и плеер 5 новых типов шагов. Каждый — отдельный компонент, тип в схеме урока, i18n (ru, uk, en), тесты.

1. story_pictures: 4 кадра (пока иконка/эмодзи + подпись «comer / una ensalada»), лицо (yo/tú/él…). Пользователь говорит 4 фразы; проверка — существующее распознавание речи с допуском на связки primero/después/luego/al final. Используем в a1.hora L5 и итоговых сценках.
2. change_person: исходная фраза + целевое лицо → выбор из 4 форм (A1) или ввод (A2+).
3. find_error: фраза с одной ошибкой в форме глагола/согласовании → тап по неверному слову → выбор правильной формы.
4. number_listen: аудио числа 0–100 → ввод цифрами; обратный режим — видим цифру, говорим вслух.
5. where_is: простая схема комнаты (SVG из готовых блоков: стол, кровать, диван, окно, коробка) + вопрос «¿Dónde está el gato?» → выбор предлога.

Генератор: change_person и find_error — только для уроков, где модуль уже прошёл соответствующие Основи (g.a1.08 / g.a1.10 / g.a1.12). number_listen — в a1.numbers. where_is — в a1.casa L4 и a1.camino L2.
Не ломай существующие шаги; npm run check зелёный.
```
